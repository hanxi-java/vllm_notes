# 感知哈希研究

## 名词解释：汉明距离 / LSH / band 数 / 鸽笼原理 / 漏召

> 背景代码注释：
> ```
> # 汉明距离阈值: 0 = 仅精确匹配; 必须 < band 数 (8), 否则鸽笼
> # 原理不成立、banding 会漏召, 故 clamp 到 7
> self._l2_max_hamming = min(int(os.getenv("EC_L2_MAX_HAMMING", "5")), 7)
> # LSH 倒排索引: (band 段号, 段值) → 该段取该值的全部已登记
> # pHash。汉明距离 ≤ τ < 8 的两个 hash 必共享至少一段 (鸽笼),
> # 故 banding 不漏召; 误候选由 hamming/grid/exists 过滤兜底
> ```

### 1. 汉明距离（Hamming distance)

两个等长二进制串**对应位上不同的位数**。

```
hash A: 10110010
hash B: 10010011
         ↑      ↑   ← 有 2 位不同
汉明距离 = 2
```

在我们的场景里，pHash 是 64 位的二进制串。两张图内容越相似，pHash 的汉明距离越小；完全不同的两张图，平均约 32 位不同（64 位里每位各有一半概率不同）。所以"相似图共享缓存"就转化成了"**在已登记的 hash 里，找出与查询 hash 汉明距离 ≤ τ 的那些**"。

### 2. 为什么需要索引：暴力查找的问题

假设缓存里已登记了 100 万个 pHash，来一个新图，要找出距离 ≤ 5 的候选。最直接的办法是挨个算距离——100 万次 XOR+数 1，每来一个请求都这么干，太慢。

麻烦在于：memcache 这种 KV 存储只支持"key 完全相同才查得到"，没法表达"找和我差不多的 key"。我们需要一个技巧，把"近似查找"转化成若干次"精确查找"。这就是 LSH。

### 3. LSH(Locality Sensitive Hashing，局部敏感哈希）

一类哈希技巧的统称，核心性质和普通哈希**正好相反**:

- 普通哈希（如 blake3)：输入变一点点 → 输出完全打乱（雪崩效应），适合精确去重；
- LSH：输入相似 → 输出**大概率相同或相近**，适合找相似项。

我们的 pHash 本身就是一种 LSH（相似的图 → 汉明距离近的 hash)。而 banding（分段）是在 pHash 之上再套一层 LSH 技巧，解决"距离近但不完全相同的 hash 怎么用精确查找找到"的问题。

### 4. band 数（分段）与倒排索引

把 64 位的 hash 平均切成 **8 段（band)**，每段 8 bit:

```
phash:  [01100101][11010000][00011110][10101010][11001100][11110000][00001111][01010101]
         band 0    band 1    band 2    band 3    band 4    band 5    band 6    band 7
```

**倒排索引**就是一张"段值 → 完整 hash"的表（正排是"hash → 它的各段值"，倒过来存，所以叫倒排）:

```
(band 0, 01100101) → {hashA, hashX, ...}     ← band 0 恰好等于这个值的所有 hash
(band 1, 11010000) → {hashA, hashY, ...}
(band 2, 00011110) → {hashA}
...
```

每张图登记时，把它的 hash 挂到 8 个桶里（每段一个桶）。

**查询时**：新图的 hash 也切成 8 段，拿 8 个 （段号， 段值） 去查表，把命中的桶里的 hash 全部收集起来作为候选——8 次 dict 精确查找，就代替了 100 万次逐个比较。候选里混着不少"只是碰巧某一段相同"的（误候选），没关系，收集完再逐个算真实汉明距离过滤掉。

### 5. 鸽笼原理（Pigeonhole Principle）与"为什么不漏召"

**鸽笼原理**：把 n+1 只鸽子放进 n 个笼子，至少有一个笼子里有 ≥2 只。推广形式：**把至多 7 个差异位撒进 8 个段里，至少有一个段里一个差异位都没有**（7 个差异位最多"污染"7 个段，8 段里必剩 1 段是干净的）。

对应到我们的场景：

- 两个 hash 汉明距离 ≤ 7 → 差异位 ≤ 7 个 → 这 ≤7 个差异位最多散落在 7 个 band 里 → **至少还有 1 个 band 完全相同** → 查询时这个 band 的桶必被查中 → 这个候选必被收集到。

所以只要阈值 τ ≤ 7,**所有真正满足条件的相似项 100% 会被收集到**，一个都不漏。

- **漏召**（漏召回）：本来满足条件（距离 ≤ τ）的项，查找时却没被找到。上面证明了 τ ≤ 7 时不会漏召。
- 但如果有人把 `EC_L2_MAX_HAMMING` 配成 8 或更大：8 个差异位可以恰好一段一个，8 段全部被污染，没有任何一段完全相同 → 倒排索引查不到它 → 漏召。这就是代码里 `min(..., 7)` 强制 clamp 的原因。

### 6. 串起来：一次完整的查询流程

假设 τ = 5，缓存里已登记图 A 的 hash，现在来了一张与 A 相似、距离为 4 的新图 B:

1. B 的 pHash 切成 8 段；距离 4 → 至少 4 个段与 A 完全相同（鸽笼保证至少 1 个，实际通常更多）;
2. 拿 8 个（段号， 段值）查 `_band_index`,A 的 hash 在共享段的桶里，被收集进候选集；桶里可能还有一堆碰巧同段的无关 hash;
3. 对候选集逐个算真实汉明距离：A 距离 4 ≤ 5 ✓；无关候选距离可能 20+，被过滤 ✗;
4. 再过 grid 门控（A 和 B 的 token 数必须相同）和 `exists` 确认（A 的 embedding 确实还在 memcache 里）;
5. 全通过 → 命中，直接复用 A 的 ViT 输出，B 跳过 ViT。

一句话总结：**banding + 倒排索引负责"快"(8 次精确查找代替全表扫描），鸽笼原理保证"不漏"(τ<8 时相似项必入候选），汉明距离 + grid + exists 三重过滤负责"不错"（误候选全部被挡掉）**。

## 问：可以图示的方式，解释一下匹配的过程和原理吗

用一个具体例子画出来：缓存里已登记 4 张图（A、C、D、E)，新来一张与 A 相似的图 B（汉明距离 4)，阈值 τ=5。

### 第 0 步：每张图先算出一个 64 位 pHash

```
图片 ──pixel_values──▶ 反解2D平面 ──▶ 灰度 ──▶ 32×32 ──▶ DCT ──▶ 左上8×8 ──▶ 与median比 ──▶ 64 bit

图A: 01100101 11010000 00011110 10101010 11001100 11110000 00001111 01010101
图B: 01100101 11010000 10011110 10101010 11001101 11110000 00001111 01010101   ← 与A有4位不同
                                                                  (在第2、4段上)
```

### 第 1 步：建索引——每个 hash 切成 8 段，挂进 8 个桶

```
                 倒排索引 _band_index
                 (段号, 段值) → 该桶里的所有 hash

 band 0:  (0, 01100101) ──▶ {A, B以后也会进这个桶}
          (0, 11100001) ──▶ {C}
          (0, 01100100) ──▶ {D}
          (0, 00110011) ──▶ {E}

 band 1:  (1, 11010000) ──▶ {A}
          (1, 00001111) ──▶ {C, D}      ← C和D碰巧第1段相同, 合租一个桶
          (1, 10101010) ──▶ {E}

 band 2:  (2, 00011110) ──▶ {A}          ← B的第2段与A不同, 以后进别的桶
          ...

   ...共 8 段 × 每种出现的段值一个桶...
```

要点：**一个 hash 同时出现在 8 个桶里**（每段一个），所以它有 8 次被别人找到的机会。

**补充：每个 band 的桶数上限是 256，但桶里的 hash 数没有上限。**

要区分两种"元素"：

- **桶的 key，即 `(段号, 段值)` 元组——每个 band 最多 256 个。** 每段是 8 bit，取值只有 2⁸ = 256 种，所以 band 0 下最多出现 256 个不同的桶（`(0, 00000000)` 到 `(0, 11111111)`），8 个 band 合计最多 8 × 256 = 2048 个桶 key。这是由段长决定的硬上限，和库里有多少 hash 无关。
- **每个桶里挂的 hash 数量没有上限。** 桶不是"一个槽位放一个 hash"，而是 `(段号, 段值) → 该桶里的所有 hash` 的倒排列表：
  - 库里有 100 万个 hash，band 0 仍然最多只有 256 个桶，但平均每个桶里装 ~100万/256 ≈ 3900 个 hash；
  - 极端情况下，如果 100 万个 hash 的第 0 段恰好都是 `01100101`，那 `(0, 01100101)` 这一个桶里就有 100 万个 hash，而其他 255 个桶是空的。

| 概念 | 上限 |
|---|---|
| 每个 band 的不同段值（桶 key 数） | 256（硬上限） |
| 每个桶里的 hash 数 | 无上限，最坏 = 整个索引大小 |
| 每个 hash 出现在多少个桶里 | 恰好 8 个（每段一个） |
| 倒排索引总条目数 | 恰好 8 × N |

另外注意"共 8 段 × 每种**出现的**段值一个桶"——实际桶数 ≤ 256/band，库里 hash 少的时候（比如只有 50 个 hash），一个 band 最多也就 50 个非空桶。

### 第 2 步：查询——B 到来，8 次取桶

```
B 的 8 个 (段号, 段值) 各自取桶:

 B段0 (0,01100101) ─▶ {A}        ✓ 取到 A！
 B段1 (1,11010000) ─▶ {A}        ✓ 又取到 A (去重)
 B段2 (2,10011110) ─▶ {}          ✗ 空桶 (B这段被差异位污染了)
 B段3 (3,10101010) ─▶ {A}        ✓
 B段4 (4,11001101) ─▶ {}          ✗ 空桶 (这段也被污染)
 B段5 (5,11110000) ─▶ {A, D}     ✓ D 碰巧这段相同, 混进来了 (误候选)
 B段6 (6,00001111) ─▶ {A}        ✓
 B段7 (7,01010101) ─▶ {A}        ✓
        │
        ▼  合并去重
   候选集 = {A, D}
```

```
为什么 A 一定能被取到? 鸽笼原理图示:

 B:     [====][====][XX≠≠][====][X≠==][====][====][====]
                  ↑差异位     ↑差异位
 A:     [====][====][YY==][====][Y===][====][====][====]
         └────┴────┴──────┴────┴──────┴──────┴──────┘
              6 个段完全相同 ── 随便哪一段的桶里都有 A
 4 个差异位最多污染 4 个段, 8 段里至少还剩 4 段是干净的
 (极端情况: 7 个差异位污染 7 段, 仍剩 1 段 ── 所以 τ 必须 < 8)
```

而 C、E 与 B 八段全不同，**从头到尾没被碰到**——100 万个这样的项也一样是零代价。

### 第 3 步：三重过滤——候选集 {A, D} 逐个过闸

```
              候选 A                    候选 D
              ─────                     ─────
闸门1 汉明距离  d=4 ≤ τ=5  ✓            d≈30 > 5  ✗ 出局 (只是碰巧同段)
闸门2 grid相同  (1,32,48)=(1,32,48) ✓
                └─ token数必须一致, 否则embedding形状对不上
闸门3 exists    memcache里还有A的embedding ✓
                └─ 被淘汰/未回填完则跳过, 不会错

   结果: 命中 A ──▶ 按 A 的 store_key 取 embedding
                   注入到 B 的 mm_hash 名下, B 跳过 ViT
```

### 全流程一图速览

```
                    查询图 B
                      │
                pHash (64 bit)
                      │
              切 8 段 (banding)
                      │
        ┌──8 次 dict.get──┐        暴力法对照: 与全部 N 个
        ▼                 ▼        登记 hash 逐个算距离
     取到桶{..}      空桶{..}      ── N 次计算, 随规模线性增长
        └────合并去重────┘
                │
           候选集 {A, D}           ← 与N无关, 通常只有几个
                │
     ┌──── hamming ≤ τ ────┐       ← 挡掉"碰巧同段"的误候选 (D)
     ├──── grid_thw 相同 ───┤       ← 挡掉"形状不匹配" (硬约束)
     └──── exists(store_key)┘       ← 挡掉"已淘汰/未回填"的软状态
                │
           命中 A → 复用 A 的 ViT embedding
```

三层角色各记一句话：

- **banding + 倒排索引** = 海选：8 次查表圈出"至少有一段相同"的极少数候选（快）;
- **鸽笼原理** = 海选的保险：τ < 8 时真相似项必在候选集里（不漏）;
- **汉明距离 + grid + exists** = 终面：候选逐个严格审查（不错）。
